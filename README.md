# Комментарии

## API Endpoints PRIVATE

### 1. Создание комментария

**Endpoint:** `POST /users/{userId}/comments/events/{eventId}`

**Описание:** добавляет комментарий от пользователя, который посетил событие.

**Параметры:**
* `userId` (`Long`) — ID пользователя, оставляющего комментарий (path variable).
* `eventId` (`Long`) — ID события, к которому оставляют комментарий (path variable).
* `NewComment` (RequestBody) — объект комментария:
    * `text` (`String`) — текст комментария.
        * Минимальная длина: 20 символов.
        * Максимальная длина: 2000 символов.

**Коды ответов:**
* `200 OK` — комментарий успешно создан.
* `400 Bad Request` — текст комментария не соответствует ограничениям (сообщение: *"Text message must be not less than 20 and no more than 2000 symbols"*).
* `404 Not Found` —
    * пользователь не зарегистрирован;
    * событие с указанным `eventId` не существует.
* `409 Conflict` —
    * пользователь является инициатором события;
    * пользователь уже оставил комментарий к этому событию;
    * у пользователя нет подтверждённого запроса на посещение мероприятия;

### 2. Обновление комментария

**Endpoint:** `PATCH /users/{userId}/comments/{commentId}`

**Описание:** обновляет текст существующего комментария.

**Параметры:**
* `userId` (`Long`) — ID пользователя, обновляющего комментарий (path variable).
* `commentId` (`Long`) — ID комментария для обновления (path variable).
* `NewComment` (RequestBody) — обновлённый объект комментария:
    * `text` (`String`) — новый текст комментария (ограничения: 20–2000 символов).

**Коды ответов:**
* `200 OK` — комментарий успешно обновлён.
* `400 Bad Request` — новый текст не соответствует ограничениям длины.
* `404 Not Found` — комментарий с указанным `commentId` не найден.
* `409 Conflict` —
    * попытку обновить комментарий совершает не автор;
    * прошло более 24 часов с момента публикации комментария.

---

### 3. Удаление комментария

**Endpoint:** `DELETE /users/{userId}/comments/{commentId}`

**Описание:** удаляет существующий комментарий.

**Параметры:**
* `userId` (`Long`) — ID пользователя, удаляющего комментарий (path variable).
* `commentId` (`Long`) — ID удаляемого комментария (path variable).

**Коды ответов:**
* `200 OK` — комментарий успешно удалён.
* `404 Not Found` — комментарий с указанным `commentId` не найден.
* `409 Conflict` —
    * попытку удалить комментарий совершает не автор;
    * прошло более 24 часов с момента публикации комментария.

---

### 4. Получение комментариев пользователя

**Endpoint:** `GET /users/{userId}/comments`

**Описание:** возвращает все комментарии указанного пользователя.

**Параметры:**
* `userId` (`Long`) — ID пользователя, чьи комментарии запрашиваются (path variable).
* `from` (`Integer`) — количество пропускаемых записей (request param):
    * значение по умолчанию: `0`;
    * минимальное значение: `0`.
* `size` (`Integer`) — количество возвращаемых записей за раз (request param):
    * значение по умолчанию: `10`;
    * минимальное значение: `1`.

**Коды ответов:**
* `200 OK` — возвращает список комментариев пользователя (может быть пустым, если комментариев нет).
* `400 Bad Request` —
    * параметр `from` отрицательный;
    * параметр `size` ≤ 0.
* `404 Not Found` — пользователь с указанным `userId` не найден.

### 5. Удаление комментария администратором

**Endpoint:** `DELETE /admin/comments/{commentId}`

**Описание:** удаляет любой комментарий по ID — операция доступна только администраторам.

**Параметры:**
* `commentId` (`Long`) — ID удаляемого комментария (path variable).

**Коды ответов:**
* `200 OK` — комментарий успешно удалён администратором.
* `404 Not Found` — комментарий с указанным `commentId` не найден в базе данных.

---

### 6. Получение комментария по ID

**Endpoint:** `GET /comments/{commentId}`

**Описание:** возвращает полный DTO‑объект комментария по его уникальному идентификатору.

**Параметры:**
* `commentId` (`Long`) — ID запрашиваемого комментария (path variable).

**Коды ответов:**
* `200 OK` — возвращает `CommentDto` с данными комментария.
* `404 Not Found` — комментарий с указанным `commentId` не существует в системе.

---

### 7. Получение всех комментариев к событию

**Endpoint:** `GET /comments/events/{eventId}`

**Описание:** возвращает список комментариев к указанному событию с поддержкой пагинации.

**Параметры:**
* `eventId` (`Long`) — ID события, чьи комментарии запрашиваются (path variable).
* `from` (`Integer`) — количество пропускаемых записей (request param):
  * значение по умолчанию: `0`;
  * минимальное значение: `0` (проверяется аннотацией `@Min(0)`).
* `size` (`Integer`) — количество возвращаемых записей за раз (request param):
  * значение по умолчанию: `10`;
  * минимальное значение: `1` (проверяется аннотацией `@Min(1)`).

**Логика пагинации:**
* Преобразует параметр `from` в номер страницы через деление на `size`: `PageRequest.of(from / size, size)`.
* Использует `Pageable` для запроса данных из репозитория.
* Возвращает только содержимое страницы (`getContent()`) в виде списка `CommentDto`.
